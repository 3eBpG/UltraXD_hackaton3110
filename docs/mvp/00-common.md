## Что собрать

Браузер → наш Python-сервер → устройства и правила → результат в браузере. Наш сервер отдельно обменивается данными с Ujin.

Сначала соединяем эту цепочку с одним правилом. Затем добавляем вход по роли, конструктор моделей, каталог и готовые сценарии. Полная проверка Ujin остаётся отдельным обязательным результатом; локальный успех её не заменяет.

## Общий API

Это адреса нашего будущего сервера, их нужно реализовать. Бэк работает на `127.0.0.1:8000`. Фронт обращается к относительным `/api/...` через Vite proxy. Не вызывать Ujin из браузера.

| Адрес | Назначение |
| --- | --- |
| `GET /api/health` | Проверить сервер. |
| `POST /api/auth/login`, `GET /api/auth/me`, `POST /api/auth/logout` | Вход, текущая роль, выход. |
| `GET /api/models`, `GET /api/models/{id}` | Каталог моделей и описание возможностей. |
| `POST /api/models`, `PATCH /api/models/{id}` | Создать или изменить модель; только администратор. |
| `GET /api/devices`, `POST /api/devices` | Устройства дома; добавить экземпляр модели. |
| `GET /api/devices/{id}`, `DELETE /api/devices/{id}` | Показания и описание; удалить экземпляр с отключением связанных правил. |
| `POST /api/devices/{id}/commands` | Выполнить команду: `{"signal":"power","value":1}`. |
| `POST /api/devices/{id}/simulate` | Новое показание эмулятора: `{"signal":"temperature","value":18}`. |
| `GET /api/scenarios`, `POST /api/scenarios` | Список правил; сохранить новое. |
| `GET`, `PATCH`, `DELETE /api/scenarios/{id}` | Открыть, изменить, включить/выключить, удалить правило. |
| `POST /api/scenarios/test` | Проверить переданное правило на отдельных копиях эмуляторов. |
| `GET /api/executions?scenario_id=...` | История выполнения правила. |
| `GET /api/templates`, `POST /api/templates`, `PATCH /api/templates/{id}` | Готовые сценарии; запись только администратору. |
| `GET /api/integration/status` | Результат обмена с Ujin. |

Успешный ответ: `{"data":...}`. Списки: `{"data":[]}`. Ошибка: `{"error":{"code":"INVALID_VALUE","message":"Температура должна быть числом","field":"condition.value"}}` и HTTP 400/422; без входа — 401, без прав — 403, нет объекта — 404. DELETE возвращает `{"data":{"deleted":true}}`.

Все идентификаторы — строки, включая серийные номера Ujin: они больше безопасного целого JavaScript. Время — ISO 8601 с часовым поясом. Не передавать токены Ujin в ответах.

Вход принимает `{"login":"...","password":"..."}`, ответ входа и `/auth/me`: `{"data":{"id":"...","role":"user"}}` или роль `admin`. Выход удаляет сессию и возвращает `{"data":{"ok":true}}`. Сессия — в cookie, роль из браузера сервер не принимает. Все адреса кроме health/login требуют входа; запись моделей и шаблонов — роли admin.

## Данные, которые оба используют

**Модель:** `id`, `name`, `description`, `image_url`, `runtime_kind`, `signals`. POST передаёт эти поля без `id`, PATCH — изменяемые поля. Для конструктора `runtime_kind:"generic"`, `image_url` — необязательная ссылка, загрузки файлов пока нет. Один элемент `signals`:

```json
{"name":"temperature","title":"Температура","type":"number","management":"r","kind":"property","unit":"°C","min":-40,"max":80,"initial":22,"capability":"temperature"}
```

`r` — чтение; `rw` — чтение и команда; `w` — только команда. Для MVP используем числа и перечисления: у состояния нагревателя `type:"enum"`, `options:[{"value":0,"label":"Выключен"},{"value":1,"label":"Включён"}]`, `management:"rw"`, `capability:"heating_switch"`. В конструкторе MVP достаточно `r/rw`; готовые эмуляторы могут содержать `w`.

**Устройство:** `id`, `model_id`, `name`, `source:"emulator"`, `signals` из модели, `state`, `status` (`ready`, `waiting_data`, `stale`). Пример состояния: `{"temperature":{"value":18,"observed_at":"2026-10-31T12:00:00+05:00"}}`. Список устройств возвращает эти же поля. Добавление: `{"model_id":"temperature_sensor","name":"Датчик в спальне"}`.

**Правило для сохранения:**

```json
{
  "name":"Согреть комнату",
  "condition":{"device_id":"sensor_1","signal":"temperature","operator":"lt","value":20},
  "action":{"device_id":"heater_1","signal":"power","value":1}
}
```

Ответ дополняется `id`, `enabled:false`, `last_execution`. Операторы: `eq`, `lt`, `gt`; для перечислений только `eq`. Включение: `PATCH` с `{"enabled":true}`.

**Шаблон:** пример объекта внутри `data`:

```json
{
  "id":"warm_room","name":"Согреть комнату","description":"Включает нагрев, когда холодно",
  "roles":[
    {"id":"sensor","capability":"temperature","access":"read","candidates":[{"device_id":"sensor_1","signal":"temperature"}],"model_ids":["temperature_sensor"]},
    {"id":"heater","capability":"heating_switch","access":"write","candidates":[],"model_ids":["heater"]}
  ],
  "missing_roles":["heater"],
  "condition":{"role_id":"sensor","operator":"lt","value":20},
  "action":{"role_id":"heater","value":1}
}
```

При записи шаблона не передавать `id`, `candidates`, `model_ids`, `missing_roles`: их формирует сервер. Для создания правила фронт заменяет каждую роль выбранной парой `device_id/signal`. `read` допускает `r/rw`, `write` — `rw/w`.

**Статус Ujin:** `{"data":{"status":"accepted_unverified","last_attempt_at":"2026-10-31T12:00:00+05:00","last_verified_at":null,"message":"Значение не получено обратным чтением"}}`. Допустимые статусы также `not_configured`, `pending`, `verified`, `error`. Он не заменяет локальное `device.status`.

**Проверка:** тело `{"scenario":<правило>,"inputs":[{"device_id":"sensor_1","signal":"temperature","value":18}]}`. Ответ внутри `data`: `result` (`confirmed`, `condition_false`, `waiting_data`, `failed`), `steps` (массив `{stage,status,message}`), `state_after` (состояния тестовых устройств по id). Тест возвращает результат без записи в рабочий журнал. В рабочем журнале те же поля плюс `id`, `scenario_id`, `created_at`.

## Поведение первой версии

- Новое правило и правило после изменения условия или действия выключено. Отдельный PATCH `enabled` меняет только активность. После включения ждём следующее свежее показание; если условие истинно, выполняем один раз. Следующее срабатывание — после перехода через ложное условие.
- Нет данных или они устарели — команду не отправляем. Начальный порог свежести для демо — 60 секунд, одно значение в настройках сервера.
- Тест не меняет работающий дом, не запускает другие правила и не публикуется в Ujin. Обязательность теста перед включением ещё не согласована; пока даём проверить, но не блокируем включение по истории тестов.
- На перезапуске восстанавливаем определения и последние значения, помечаем значения устаревшими и выключаем правила. Пользователь явно включает их заново.
- Определение используемой модели пока не меняем: возвращаем 409 `MODEL_IN_USE` и предлагаем создать копию. Версии моделей позже.

## Общая проверка перед сдачей

Админ создаёт модель с новым показанием → пользователь добавляет её экземпляр → создаёт правило → тестирует → включает → меняет показание → получает подтверждённое действие и запись истории. Выключенное правило не действует. Обновление страницы не теряет данные. Готовый сценарий находит недостающее устройство и позволяет вернуться из каталога к настройке.
